# 春秋（Spring and Autumn）

> 一款从零自研的 2D 平面即时策略对战游戏，背景设定在春秋时期。目标是不依赖任何商业游戏引擎，打造一个注重**公平竞技**、支持**局域网/多人联机**，并具备多层级征服与历史演进机制的纯策略游戏。

---

## 📖 项目简介

本项目是一个个人长期实践项目。游戏的灵感来源于《大秦帝国》与《红警》的结合——剥离重度氪金与数值碾压，保留招募与养成乐趣，将核心聚焦于**“古代战场模拟 + 即时战术操作 + 公平多人对抗”**。

游戏从春秋乱世开局，玩家需要通过铺路、占领、经营、招募，逐步扩张势力。最终目标是在局域网或服务器环境下，实现多名玩家同图争霸，靠实力与运气问鼎中原。

---

## ✨ 核心特性与进度

- [x] **底层架构**：逻辑与渲染彻底分离，`logic/` 层完全不依赖 SDL，保证底层计算的纯净与高效。
- [x] **无头测试模式**：支持无窗口极速批量模拟，内置多策略 AI（随机、激进、稳健），用于自动化平衡性测试。
- [x] **格子化地图与铺路**：100x100 网格地图，支持摄像机平滑移动、缩放、坐标转换。部队只能从己方领地出发，一格一格推进占领。
- [x] **经济与招募系统**：木材、铁矿、粮草产出，大营、兵营、伐木场等建筑系统。包含武将、名士、招贤令抽卡、寻访与招降机制。
- [x] **战斗系统**：简化的格子遭遇战，支持攻击力、血量、死亡结算。
- [x] **主机权威架构（开发中）**：基于前期局域网战术版经验，正在将 `Project2` 的逻辑层重构为支持**主机权威（Host-Authoritative）**的模式，为后续的多端同步做准备。
- [ ] **局域网多人对战**：支持 2~4 名玩家在同一大地图上争霸，同步格子归属、资源产出、单位行军与战斗状态。

🎮 游戏机制概述
资源循环：大营提供基础产出，占领资源点并建造对应设施（伐木场等）可大幅提升效率。

武将获取：

新手池：开局免费抽取。

招贤令：通过占领资源点、完成任务获取，有每周/每赛季获取上限。

寻访：派遣名士前往特定地点，名士智力与口才越高，越容易发现高品质武将。

招降：攻破敌方城池后，有一定几率招降敌方武将。

战斗与克制：单位具有攻击力、攻速、血量。目前为简化版战斗，后续将加入兵种克制、地形影响与士气机制。

格子争夺：无法自由跨越地图，必须从己方或中立格子逐格推进，停留占领，形成铺路网络。

🌐 联机架构与设计思路
本项目的联机部分并非简单的状态复制，而是基于主机权威模型（Host-Authoritative）进行底层设计：

主机运行完整逻辑：所有战斗计算、资源产出、行军结算都在主机端完成。

客户端仅发送指令：客户端（玩家）只发送“移动”、“攻击”、“建造”等指令请求。

状态广播：主机验证指令合法性后，以固定频率（如 20Hz）向客户端广播当前游戏状态快照。

防作弊机制：客户端无法直接修改资源或单位血量，彻底杜绝外部篡改和作弊，保证公平竞技。

🤝 贡献与开发原则
核心逻辑纯净：logic/ 目录下禁止包含任何 <SDL3/...> 头文件。

联机安全原则：实现联机时，必须遵循主机权威逻辑。客户端只发送指令，主机计算后广播状态。

AI 驱动测试：任何核心数值或机制的修改，必须先在无头模式下跑通至少 100 局 AI 对战，确保无崩溃。

提交规范：欢迎提交 Issue 或 Pull Request。提交前请确保代码可以在 Debug | x64 下无警告编译通过。
